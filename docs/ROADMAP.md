# ROADMAP — 기능 단위 백로그

> **순서를 건너뛰지 않는다.** 뼈대(B)가 선 다음에 기능(F)을 붙인다.
> 한 단위 = 프로토 → 스펙 → 구현. **표의 칸 하나가 한 사이클**이고, 한 사이클에
> 두 칸을 채우지 않는다.
> 진행 중 발견한 일감은 이 문서 맨 아래 "발견한 일감"에 **추가만** 한다 —
> 사이클 안에서 몰래 하지 않는다(v3에서 사이클이 비대해진 경로).

표기: `-` 미착수 · `~` 진행중 · `v` 완료

## 뼈대 (B) — 이 순서를 바꾸지 않는다

| # | 단위 | 프로토 | 스펙 | 구현 | 이 단위가 답해야 하는 것 |
|---|------|:---:|:---:|:---:|--------------------------|
| B1 | 세 영역 골격 · 공통/영역별 테이블 구조 | - | - | - | BACKBONE §4의 1~3번 — 공통:영역별이 1:1인가, phase를 어디에 두는가 |
| B2 | 영업 프로젝트 (목록 · 등록 · 상세) | - | - | - | 영업에만 있는 컬럼은 무엇인가 |
| B3 | 솔루션 프로젝트 (목록 · 상세) | - | - | - | 솔루션에만 있는 컬럼은 무엇인가 |
| B4 | 유지보수 (계약 · 사이트 · 목록 · 상세) | - | - | - | BACKBONE §4의 4번 — 원천이 프로젝트인가 계약인가 |
| B5 | **이관 파이프라인** 영업→솔루션→유지보수 | - | - | - | BACKBONE §4의 6번 — 이관의 조건·권한·되돌릴 수 없음 |

B5까지 끝나면 이 제품의 줄기가 선다. 그 전에는 아래 F를 시작하지 않는다.

## 기능 (F) — 줄기에 붙이는 것

| # | 단위 | 프로토 | 스펙 | 구현 | 선행 |
|---|------|:---:|:---:|:---:|------|
| F1 | 인력 · 조직 · 직급 | - | - | - | B2 |
| F2 | 프로젝트 인력 배정 | - | - | - | B3 · F1 |
| F3 | 가동률 (월별 합산 · 직급 보정 · 오버부킹) | - | - | - | F2 |
| F4 | 알람 / 알림 | - | - | - | B5 |
| F5 | 권한 (조직 가시성 + 프로젝트 역할) | - | - | - | F1 |
| F6 | 유지보수 이슈 관리 | - | - | - | B4 |
| F7 | 감사 로그 | - | - | - | B5 |
| F8 | 홈 / 대시보드 | - | - | - | B5 |
| F9 | MCP / AI 챗 — v3 자산 재활용 검토 | - | - | - | B5 · F3 |

F의 순서는 선행만 지키면 사용자가 바꿀 수 있다. B는 바꾸지 않는다.

**F9(MCP)는 다른 F와 동급이다.** 앞당겨 아키텍처에 반영하지 않는다 —
v3는 MCP가 제품이었고, 그래서 PMS가 MCP 모양으로 휘었다(호스트 앱 분리 ·
도구 카탈로그 · 2인 트랙 분리). v4는 단일 트랙이다.
