# 뼈대 (BACKBONE) — 확정 스펙이 아니라 출발 스케치

> **한 페이지를 넘기지 않는다.** 단위별 확정은 `docs/features/<NN-slug>.md`에 쓴다.
> 이 문서를 고치는 변경은 반드시 `PROGRESS.md` 결정 기록을 남긴다.
> 여기 적힌 것은 "이렇게 갈 것 같다"이고, **프로토타입이 확인해 주기 전까지는 근거가 없다.**

## 1. 세 영역

| 영역 | 다루는 구간 | 대표 화면 |
|------|-------------|-----------|
| 영업 | 수주 이전 — 제안·견적·계약 진행 | 영업 프로젝트 목록 · 상세 |
| 솔루션 | 수주 이후 — 구축 수행 | 솔루션 프로젝트 목록 · 상세 |
| 유지보수 | 납품 이후 — 계약·사이트·이슈 | 유지보수 계약 목록 · 상세 |

## 2. 프로젝트 테이블 구성 (2026-09-19 프로토타입으로 확정)

공통 컬럼 테이블 하나 + 영역별 테이블. **영역별 행은 프로젝트당 1개(1:1).**

```
project (공통)  id · 고객사 · 프로젝트명 · 솔루션 · 담당자
  ├── sales_project      1:1   단계 · 예상 수주액 · 예상 착수 · 영업대표 · 메모
  ├── solution_project   1:1   상태 · 계약 M/M · 기간 · 진행률 · 투입 인력
  └── contract           1:1?  상태 · 기간(1년) · 계약금액 · 영업대표   ── 사이트 1:N
```

- **이관해도 행을 지우지 않는다.** 상태만 바뀌고 `closedAt`이 찍힌 채 남는다.
- **이관 내역은 저장하지 않는다.** 위 세 행의 `openedAt`/`closedAt`에서 파생한다
  (원본 이중화 금지). 이관 로그 테이블을 따로 두면 그것과 실제 행이 어긋나는 날이 온다.
- **현재 영역도 파생이다.** 목록을 가르는 기준은 `phase` 컬럼이 아니라
  **"그 영역의 행을 가지고 있는가"**다. 그래서 이관해도 원래 영역 목록에 남는다.
- **영역 안의 세부 상태는 영역별이다** — 영업 `리드·제안·견적·수주` /
  솔루션 `진행 전·진행·검수·완료` / 유지보수 계약 `신규·유지·종료`. 공통 상태값은 없다.
- **유지보수의 원천은 계약이다** (프로젝트가 아니다). 계약:사이트 = 1:N,
  이슈는 사이트에 붙는다. 이관 없이 직접 등록하는 계약도 있다(OEM).

## 3. 이관 파이프라인 (이 프로젝트의 줄기)

```
영업 ──수주──▶ 솔루션 ──진행률 100%──▶ 유지보수(계약)
```

- 이관은 **명시적 행위**다. 상태값을 바꿨다고 자동으로 넘어가지 않는다.
- **역방향 이관 금지.** 되돌림이 필요하면 별도 단위로 기획한다.
- **진행률 100%는 유지보수 이관의 전제조건**이다 — 100%가 되어야 이관 버튼이 나타난다.
  100% 자체는 상태를 바꾸지 않는다. **완료는 이관이 만든다.**
  (v3는 진행률 쓰기가 상태 전이 권한을 우회해 자동 전이를 폐지했다. 여기서는 100%가
  버튼을 열어 줄 뿐이라 같은 구멍이 생기지 않는다.)
- **유지보수 계약 기간은 1년 고정** — 시작일을 받고 종료일은 자동 계산한다.
- 이관된 건은 원래 영역 목록에서 **읽기 전용**으로 남는다.
- 가동률·알람·권한·감사 같은 기능은 **이 줄기에 붙이는 것**이다. 줄기가 서기 전에는 만들지 않는다.

## 4. 미확정 — 다음 프로토타입·스펙이 확인할 것

> 확인될 때마다 해당 줄을 지우고, 그 결정을 `PROGRESS.md` 결정 기록과 단위 스펙으로 옮긴다.

- [ ] **계약 갱신** — 계약이 1년 고정이라 갱신하면 `project : contract`가 1:N이 된다.
      새 계약 행으로 볼지, 기존 계약의 기간 연장으로 볼지 (B4). §2의 `1:1?`가 이것이다
- [ ] 영업 단계에서 고객사·프로젝트명이 아직 확정되지 않았을 때의 표현 (B2)
- [ ] 이관에 **권한**이 붙는가 — 누가 이관 버튼을 누를 수 있는가 (B5 · F5)
- [ ] 이관된 건이 계속 쌓이는 목록 — "진행 중만" 필터가 기본이어야 하는가 (B2 · B3)
- [ ] 이관된 건을 수정해야 할 때의 경로 (B3)
- [ ] 솔루션 영역에서 **자체 생성**을 허용하는가 — 허용하면 "모든 프로젝트는 영업을 거친다"가 깨진다 (B3)
- [ ] 이관 시 사이트를 몇 개까지 받는가 — 계약:사이트가 1:N인데 이관은 1개만 만든다 (B4)
